WorkPilot 面试追问小抄

A4 排 3 × 2 共 6 张卡；打印后沿边框剪开，正面带去面试。每张卡：机制 → 常见追问 → 应答 → 陷阱。

亮点 01

支持域门是一等状态

模型调用前用 IntentGate 判定三类：EXECUTABLE / NEEDS_CLARIFICATION / REJECTED，越权与无界请求在调模型之前就挡掉。
追问
为什么不直接让模型判？
答：分类结果要进 TaskStatus 一等状态，下游校验、澄清、拒绝是三条不同处理路径；模型不可被注入篡改的稳定性需求。
× 别只说"为了安全"——说出"状态机一等状态"才是真细节。
亮点 02

参数哈希审批

预览时算一次 parameter_hash，执行前再算，不一致则 APPROVAL.EXPIRED。
追问
为什么不直接禁止修改参数？
答：审批后参数经常需要细化（cc、加附件、改收件人）。关键是防 TOCTOU，不是禁止修改。
× 这是 TOCTOU，不是权限校验。说出 TOCTOU 才显得内行。
亮点 03

lookup-before-retry

连接器超时/响应丢失时账本标 UNKNOWN，重试前必须 adapter.lookup() 查远端，不盲目重试。
追问 / 数据
追问：查远端也查不到怎么办？
答：保持 UNKNOWN，进入 recovery_cases 队列等人工对账。
同动作 100 次投递，远端只产生 1 个对象（离线确定性）。
× 别说"避免了所有重复"——只针对"响应丢失"场景。
亮点 04

规划永不静默失败

模型输出 JSON Schema 校验 + 一次 repair；仍不合法回退 DemoPlanner，恒定给出可审计的最小计划。
追问
模型持续乱输出怎么办？
答：确定性的 DemoPlanner 内置周报、会议跟进、Issue 汇总三个模板；模型挂 ≠ 任务挂。
× 别说"提高稳定性"——说"规划路径总有合法输出，回退是设计而非兜底"。
亮点 05

重规划隔离已完成副作用

diff_plans() 显式 raise，禁止删除或修改已 SUCCEEDED 步骤，避免重复触发远端写入。
追问
如果就是想撤回一个已发邮件？
答：那是显式 cancel + 回滚流程，不在 replan 范围。重规划只调整后续路径。
× 别扯"revert"——仓库只有 cancel / pause / resume，没有通用 undo。
亮点 06

60 条任务集进 CI

版本化数据集 + workpilot-eval --enforce-safety 进入 GitHub Actions，安全零容忍门禁把 Agent 行为从"调通就行"变成可回归的工程指标。
追问 / 数据
追问：怎么测真实模型？
答：搭了 workpilot-model-eval 双模型工具链，本地无外部凭证没跑。
180 次离线确定性回归，未授权写入 0.3333 → 0
× 数字必须带"离线确定性"前缀，否则会被追问真实模型数据。
